# Теория

## Определение. Примеры

> Хэш-таблица - структура данных, где доступ к данным осуществляет по специальному ключу и за каждому ключу соответствует определенное значение.

Мы видим различные реализации хэш-таблиц в разных языках программирования: объект в JavaScript, словарь в Python и так далее. Но сейчас нам предстоит реализовать эту структуру данных на языке программирования Си.


## Хэш-функция. Общий план

Мы имеем какое-либо уникальное значение, выраженное массивом символов или числом. Это значение мы передаём в специальную **хэш-функцию** , которая генерирует числовое значение. Затем это числовое значение мы преобразуем в **индекс** и уже по этому индексу записываем данные в ячейку динамического массива в формате ключ-значение.

## Коллизии

**Определение:** коллизия возникает, когда двум разным ключам соответствует один и тот же индекс в массиве (одно и то же значение хеш-функции или разное значение, но после приведения к размеру таблицы дающее одинаковый индекс).

Коллизии неизбежны, потому что:
- Размер таблицы конечен, а множество возможных ключей бесконечно.
- Хеш-функция несовершенна.

**Задача:** научиться хранить несколько элементов в одной «ячейке», либо находить альтернативные свободные места.

---

## Способы разрешения коллизий

Делятся на два больших класса: **метод цепочек** (закрытая адресация) и **открытая адресация**.

### 1. Метод цепочек (chaining)
Каждая ячейка массива («корзина») хранит не одиночный элемент, а связный список (или другую структуру) всех пар ключ-значение, попавших в эту ячейку.

**Особенности:**
- Прост в реализации.
- Таблица может хранить произвольно много элементов (даже больше размера массива).
- При плохой хеш-функции или большом количестве коллизий отдельные цепочки становятся длинными, и время операций деградирует от O(1) до O(n).
- Не требует обязательного рехеширования при повышении нагрузки, но его всё равно проводят для сохранения средней длины цепочек близкой к константе.

### 2. Открытая адресация (open addressing)
Все элементы хранятся прямо в массиве. При коллизии ищется другая свободная ячейка по некоторому правилу. Виды проб (поиска следующей ячейки):

- **Линейное пробирование (linear probing):** индекс = (hash(key) + i) % size, i = 0,1,2,…  
  Плюсы: кэш-дружелюбность. Минусы: образование кластеров (групп занятых ячеек), что ведёт к деградации.
- **Квадратичное пробирование (quadratic probing):** индекс = (hash(key) + c1·i + c2·i²) % size.  
  Уменьшает кластеризацию, но требует внимательного выбора констант, чтобы покрыть всю таблицу.
- **Двойное хеширование (double hashing):** индекс = (hash1(key) + i · hash2(key)) % size.  
  Использует вторую хеш-функцию для вычисления шага. Обеспечивает хорошее распределение, одна из лучших техник открытой адресации.
- **Удаление** в открытой адресации сложное: нельзя просто обнулить ячейку, иначе сломается цепочка поиска; вместо этого помечают её как «удалённую» (tombstone) и при вставке могут занять это место, а при поиске — пропускать.

## Хеш-функции

Назначение: преобразовать ключ (строку, число) в целое число, которое затем отображается на индекс массива через операцию взятия остатка от деления (или другую). Требования к хорошей хеш-функции:
- Детерминированность: одинаковый ключ всегда даёт одинаковый хеш.
- Быстрое вычисление.
- Равномерное распределение ключей по таблице (минимизация коллизий).
- По возможности использовать все биты ключа.

**Примеры хеш-функций для строк:**
- **djb2** (Dan Bernstein): `hash = 5381; for each char: hash = ((hash << 5) + hash) + c;` (т.е. `hash * 33 + c`).
- **sdbm**: `hash = 0; for each char: hash = c + (hash << 6) + (hash << 16) - hash;`
- **Jenkins one-at-a-time**: простое и эффективное.
- Для целых чисел часто используют мультипликативный метод или просто `key % size`.

Размер таблицы обычно выбирают простым числом (для уменьшения закономерностей при делении по модулю) или степенью двойки (для быстрого битового AND). При использовании метода цепочек размер может быть составным.

## Коэффициент заполнения (load factor) и рехеширование

**Коэффициент заполнения (α) = количество элементов / размер таблицы.**

При α выше определённого порога (часто 0.7 для открытой адресации и 1.0 для цепочек) производительность операций падает, и необходимо **рехеширование (rehashing)**:
- Создаётся новый массив, обычно в 2 раза большего размера (желательно простое число).
- Все элементы из старой таблицы вставляются в новую (с пересчётом индекса, так как размер изменился).
- Старая таблица освобождается.

**Особенности рехеширования:**
- При открытой адресации нужно перехешировать всё, так как индексы меняются.
- При цепочках можно просто перераспределить узлы по новому массиву.
- Рехеширование — дорогая операция (O(n)), но амортизированная стоимость вставки остаётся O(1), если увеличение размера происходит достаточно редко.

Выбор порога зависит от метода разрешения коллизий и желаемой производительности. Для открытой адресации часто α ≤ 0.5–0.7, для цепочек можно поднять до 1.0 и выше, но тогда выигрыш в памяти снижается.
